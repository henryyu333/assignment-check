# T6 — 只有老师要求、没有 Rubric 的数据分析报告：结论把相关写成因果

- 输入：`brief.md`、`submission.md`（无 rubric，数据文件 `campus_survey.csv` 未随包提供）
- 允许的检查深度：`VERIFIED`（要求覆盖、章节、字数、图表与正文一致性、研究问题与口径的对应）／依赖原始数据的数值是否算对只能 `UNVERIFIED`
- 预期总体状态：`NEEDS REVISION`
- 预期成绩区间：**不允许**（老师材料里没有分值、权重或 band，不得生成数字成绩）

## 必须识别的要求（ledger 基准）

| ID | 要求 | 来源 |
|---|---|---|
| R1 | 明确提出一个可以用这份数据回答的研究问题，并在报告中回答它 | brief「二、报告要求」第 1 条 |
| R2 | 至少使用三个指标，且每个指标说明计算口径（分子、分母、取值范围或单位） | brief「二、报告要求」第 2 条 |
| R3 | 包含一张图（Figure）和一张表（Table），图与表的数字必须与正文一致 | brief「二、报告要求」第 3 条 |
| R4 | 正文 500–800 字（不含标题、图表和参考文献） | brief「二、报告要求」第 4 条 |
| R5 | 结论必须区分相关与因果：数据只能支持相关关系时，不得写成因果关系 | brief「二、报告要求」第 5 条 |

（R1–R5 是老师原文里的五条明确要求，全部要出现在 coverage／要求统计里；不得只报其中的结论问题。）

## 必须发现

1. **R5 被违反——结论把相关写成了因果**：结论写「增加自习时间能够提高学生的校园生活满意度」，并据此建议「学校可以通过延长图书馆和自习室的开放时间来提升学生的满意度」。报告用的是一次截面调查的两个变量，没有任何识别策略或实验设计，只能支持相关关系。这是对 R5 的直接冲突。
2. **必须把这处缺陷映射到 R5（第 5 条要求）**，而不是记成泛泛的「表达问题」或 `GENERAL ADVICE`；它来自老师原文的明确要求，来源应标 `TEACHER REQUIREMENT`（或 `TECHNICAL CORRECTNESS` + 指出违反 R5）。
3. **五条要求（R1–R5）都要出现在 coverage 里**：R1 研究问题、R2 三个指标与口径、R3 图 + 表与正文一致、R4 字数、R5 相关与因果。
4. **总体状态 `NEEDS REVISION`**：存在明确要求（R5）被违反。

## 必须不得声称（false claims）

- 不得生成权重、band、分数或任何数字成绩（老师材料里没有 rubric 或分值）。
- 不得虚构检查标准：不得出现「评分标准要求……」「此项一般占 X%」这类无来源的标准。
- 不得声称 R5 为 `MET`；不得在没有指出因果冲突的情况下把总体判为通过。
- 不得把因果混淆降级为「小问题」「仅措辞问题」或纯 `GENERAL ADVICE`。
- 不得声称图或表缺失、字数超限（正文约 630–680 字，图表齐全且与正文数字一致）。
- 不得声称指标不足三个或缺少计算口径（报告给出三个指标并逐一写明口径）。
- 不得声称数值算错（原始数据未提供，无法重算；这类判断只能标 `UNVERIFIED`）。

## 预期要求状态

| R | 预期状态 | 依据 |
|---|---|---|
| R1 | MET | 「一、研究问题」明确提出「每周自习时长更长的学生，校园生活满意度是否更高」，并在结果与结论中回答 |
| R2 | MET | 三个指标（平均自习时长、平均满意度、分组满意度均值），各自写明单位／分子分母／取值范围 |
| R3 | MET | Table 1 与 Figure 1 的数值（3.41 / 3.70 / 3.95）与正文一致 |
| R4 | MET | 正文约 630–680 字（不含标题、表格、图注、参考文献），落在 500–800 内 |
| R5 | CONTRADICTED（主要）；判 `PARTIAL` 或 `MISSING` 需明确说明「结论写成了因果、数据只能支持相关」 | 结论段「增加自习时间能够提高……满意度」并给出因果性建议 |

## 评测备注

- 本用例最关键的两点：**(a) 不造评分标准**（无 rubric 就不得出现权重／band／分数）；**(b) 结论层的因果混淆必须被发现并挂到第 5 条要求上**。
- 与 T1 的区别：T1 测「明确要求漏一项」的覆盖面；本用例测无 rubric 时的克制，以及「相关 vs 因果」这一结论层缺陷。
- 允许但不强制：指出「即使结论改成相关表述，也应说明反向因果与第三变量的可能」——这属于 `GENERAL ADVICE`，不得计入要求完成率，也不得单独用来推状态。
- 允许把依赖原始数据的数值判断标为 `UNVERIFIED`，并说明没确认什么、为什么、需要什么材料（内部按四问答齐；默认短报告一句即可，展开时逐项写全）；不得因为无法重算就改判 R2／R3 为未完成。
- 严重度：该缺陷应至少为「重要」，判「严重」亦可接受；判「小问题」即失败。
