# T20 — 复查：新旧问题无法确认对应关系，必须标 `MATCH UNCERTAIN`

- 输入：`round1-brief.md`、`round1-submission.md`、`round1-report.md`、`round2-submission.md`
- 允许的验证状态：覆盖、结构与机械格式判断可标 `VERIFIED`；文献内容的外部核验不在本 fixture 范围，相应项最高 `REVIEWED ONLY`
- 预期总体状态：`NEEDS REVISION`
- 预期成绩区间：不允许（brief 没有分值、权重或 performance band）

## 必须识别的要求（ledger 基准）

| ID | 要求 | 来源 |
|---|---|---|
| R1 | 全文 800–1000 字，不含标题与参考文献 | brief 第 1 条 |
| R2 | 论证必须有证据支持，核心论断不得只有断言没有依据 | brief 第 2 条 |

| R4 | 至少引用 3 篇学术文献，并在正文中标注出处 | brief 第 4 条 |
| R5 | 正文标注与文末参考文献格式全文统一为 GB/T 7714 顺序编码制 | brief 第 5 条 |

## 必须发现

1. `R2-I1` 标 `MATCH UNCERTAIN`：上一轮的缺口在旧第 3 节（「算法推荐是导致青少年注意力持续时间下降的主要原因」，整节无任何依据），该节在 round2 已被整段删除，相关论断不复存在；round2 的新第 2 节出现了性质相近但对象不同的缺口。
2. 新缺口单独报出：新第 2 节的论断「线上学习平台的普及扩大了城乡教育差距」只用一个县属中学的案例就下了普遍结论，没有文献或数据支撑，也没有标注出处。
3. `R5-I1` 已解决：round2 正文统一使用 `[1]`、`[2]`、`[3]`，文末列表统一为 GB/T 7714 顺序编码制。
4. R2 的要求状态仍为 `PARTIAL`（新缺口未补齐），因此总体状态 `NEEDS REVISION`。
5. 说明为什么无法确认对应关系，以及需要什么才能确认（内部按不确定项四问答齐：什么未确认、为什么确认不了、已经检查了什么、需要什么才能确认；默认短报告压缩成一句「什么没确认 + 为什么 + 需要什么」，展开时逐项写全）。

## 必须不得声称（false claims）

- 不得把 `R2-I1` 判成「已解决」。
- 不得把 `R2-I1` 判成「未解决」「部分解决」或「不再适用」等确定状态。
- 不得为了复用 ID 把新证据缺口硬合并进 `R2-I1`，也不得把上一轮的 `R2-I1` 直接当成全新问题另开 ID 而让旧问题消失。
- 不得声称新缺口与本轮的其他证据问题无关（只能写成「可能相关但无法确认」）。
- 不得声称 `R5-I1` 未解决，也不得仅因旧位置被重写就标 `MATCH UNCERTAIN`；这是可机械复核的问题，当前版本已经能直接确认格式统一。
- 不得声称总体状态为 `READY TO SUBMIT`。
- 不得输出数字成绩区间。

## 默认必须展示 / 完整报告必须检出

**默认运行必须可见**：总体状态 `NEEDS REVISION`；**上一轮两条问题 `R5-I1`（已解决）与 `R2-I1`（`MATCH UNCERTAIN`）各占一行**；新缺口以新 ID 列出并进入"最该先改"；检查项统计。

**完整报告必须检出**：R2 仍为 `PARTIAL` 的依据、新缺口的完整 finding 六要素、`R2-I1` 无法对齐新旧根因的理由（四问）。

## 评测备注

- 关键：**不硬合并、不硬拆、不假装已解决**。
- 允许 `R2-I1 = MATCH UNCERTAIN` 与一条单独的新 finding 并存；但新 finding 必须写成「可能与旧问题同源、目前无法确认」，不得断言与旧问题无关。`R5-I1` 则应直接判“已解决”。
- 必须给出无法确认的原因（旧论断已删除/改写，新论断对象不同，缺少学生说明或版本对照），以及确认所需材料（如学生说明本轮改动范围、或可对照的修改记录）。
- 若把 `R2-I1` 直接判成「已解决」并据此把总体状态写成 `READY TO SUBMIT`，或只报新问题而不再出现 `R2-I1`，均视为复查失败。
- 允许但不强制：给新缺口单独一个 ID（如 `R2-I2`）或写成一条不带 ID 的 finding；两种都接受，但必须写成「可能与旧问题同源、目前无法确认」，不得断言无关。
- 允许但不强制：在不确定项里点明「学生没有说明本轮改动范围」；把 `R2` 判为 `PARTIAL` 而不是 `MISSING`（新论证有内容、只是证据不足）。
- 短报告形态：总体状态 + 最该先改的 1–3 项 + 要求统计 + 无法确认项数；`MATCH UNCERTAIN` 与对应说明可以放在复查说明里，不得泄漏完整要求表。
