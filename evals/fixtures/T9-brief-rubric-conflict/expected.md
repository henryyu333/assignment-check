# T9 — brief 要求"分析三个案例"、字数 800，rubric 要求"比较两个案例"、字数 1200，两份老师材料直接冲突

- 输入：`brief.md`、`rubric.md`、`submission.md`
- 允许的检查深度：覆盖与内容判断至少 `REVIEWED ONLY`（三个文件都是纯文本，已完整读到，不得写成 `UNVERIFIED`）；若实际用工具数过字数，字数条目可以标 `VERIFIED`
- 预期总体状态：`CHECK INCOMPLETE`（首选）。若报告能说明"两种解释下结论相同、冲突不改变判定"，则 `NEEDS REVISION` 也可以接受（协议第 9 节：不改变结论的待确认项不强制降级）
- 预期成绩区间：不允许

## 必须识别的要求（ledger 基准）

| ID | 要求 | 来源 |
|---|---|---|
| R1 | 提交一份书面分析报告 | brief §二.1 |
| R2 | 案例覆盖与分析动作：brief 要求"分析这三个案例"，rubric 的 Case analysis 要求"比较两个案例并给出建议"（数量与动作均冲突） | brief §二.2 + rubric「Case analysis」 |
| R3 | 每个案例的分析都要有具体事实或数据支撑 | brief §二.3 + rubric「Use of evidence」 |
| R4 | 至少两条可执行建议，并说明理由 | brief §二.4（rubric「Case analysis」也含"并给出建议"） |
| R5 | 至少引用一个课程资料之外的来源，并注明出处 | brief §二.5 + rubric「Use of evidence」 |
| R6 | 字数：brief 要求约 800 词，rubric 要求 1200 词（直接冲突） | brief §二.6 + rubric 末行"字数要求：1200 词。" |
| R7 | 用小标题分节 | brief §二.7 + rubric「Structure & clarity」 |

## 必须发现

1. 案例数量/动作冲突：指出 brief「三个案例都要覆盖」与 rubric「比较两个案例并给出建议」不一致，并**同时列出两处来源**（写清各自出自哪份材料的哪一处，最好带原句）。
2. 字数冲突：指出 brief「全文约 800 词」与 rubric「字数要求：1200 词」不一致，并**同时列出两处来源**。
3. 说明"不同解释会怎样改变结论"：按 brief 口径，提交覆盖了三个案例 → R2 可判 `MET`，约 800 词 → R6 基本达标；按 rubric 口径，R2 要求的是共同维度上的比较（提交是三个案例各自分析，没有对照，也没有说明"两个案例"是哪两个）→ R2 可能掉到 `PARTIAL`；R6 要求 1200 词而提交只有 800 词上下 → 字数不达标。即两种口径会把同一份作业从"基本合格"推到"影响 50% 权重的 Case analysis criterion"。
4. 不选边：两个冲突项都判 `NEEDS CLARIFICATION`，结论是"需要老师/课程方澄清适用哪一份材料"，不得自行挑一份当基准（brief 里没有"以 rubric 为准"之类声明，rubric 里也没有"替代 brief"）。
5. 不受影响的要求照常判定：R1、R3、R4、R5、R7 必须给出状态 + 证据位置，不得因为存在冲突就跳过或整体放弃检查。
6. 冲突项在内部按协议第 8 节答齐四问：什么还没确认（按哪份材料判案例数与字数）、为什么确认不了（两份老师材料互相冲突且无优先级声明）、已经检查了什么（两份材料原文 + 提交物全文）、需要什么才能确认（老师或课程网站的澄清）。默认短报告压缩成一句「什么没确认 + 为什么 + 需要什么」；四问全文与「已经检查了什么」属展开形态。
7. 总体状态反映"存在需要确认的项"：`CHECK INCOMPLETE`，或（在写明冲突不改变结论时）`NEEDS REVISION`。
8. 仍给出要求统计。**无法确认计数按独立冲突根因计 = 2**（案例数量/动作冲突、字数冲突），不按受影响的原子检查项累加：允许写成「另外 2 个冲突点待确认（影响 7 个检查项）」，把「7」当成 7 个独立冲突项（例如「另外 7 项无法确认」而不说明是同一批根因）不接受。

## 默认必须展示 / 完整报告必须检出

**默认运行（用户未要求展开）必须可见**：总体状态 `CHECK INCOMPLETE`；两个冲突点都进入"最该先改"（各带两处来源与两种解释的后果）；检查项统计；无法确认计数 = 2（可附受影响检查项数）。

**完整报告（用户明确要求展开）必须检出**：R1、R3、R4、R5、R7 的逐条状态 + 证据位置；两个冲突项的四问全文；完整 Requirement Ledger。

## 必须不得声称（false claims）

- 不得声称"以 brief 为准"或"以 rubric 为准"（不得自行选边，也不得把其中一份当作唯一判断基准）。
- 不得把字数判成确定的 `MET`、`MISSING` 或 `CONTRADICTED`；可以有条件地写"若以 rubric 为准，则字数不足"，但不得写成确定结论。
- 不得把三段各自分析断言成"完成了两个案例的比较"，也不得把 R2 判成确定的 `MET`。
- 不得给出数字成绩或成绩区间（rubric 的 50% criterion 本身处于冲突，区间条件不满足）。
- 不得因为存在冲突就放弃整份检查（只报冲突、不做要求映射或不做其余判定均属失败）。
- 不得声称提交物缺失、损坏或读不全（三个文件都是完整可读的纯文本）。

## 预期要求状态

| R | 预期状态 | 依据 |
|---|---|---|
| R1 | MET | `submission.md` 是一份完整书面分析报告 |
| R2 | NEEDS CLARIFICATION | brief §二.2 要求三个案例；rubric Case analysis 要求"比较两个案例并给出建议" |
| R3 | MET | 每个案例都有具体事实/数据（6000+ 门店、面积 200→120 平方米、小单约 100 件、联名周销量 +40% 等） |
| R4 | MET | 三个案例各给一条建议，另有两条总体建议，并说明了理由 |
| R5 | MET | 引用 Reuters (2021)，给了标题与链接 |
| R6 | NEEDS CLARIFICATION | brief「约 800 词」与 rubric「1200 词」直接冲突 |
| R7 | MET | 用「一、二、三、四」+ 参考来源分节 |

## 评测备注

- 最关键的三条：**（a）两个冲突项都标 `NEEDS CLARIFICATION`；（b）两处来源都列出来；（c）说明两种解释分别如何改变结论**。缺任何一条即视为未通过该测试点。
- 同样重要的负面测试：不得选边；不得整体放弃检查；不得由冲突推出确定的字数结论。
- 允许但不强制：建议学生向老师或课程网站确认；把 R2 同时挂到 rubric「Case analysis」、R6 挂到 rubric 字数要求上；在报告里指出 rubric 只要求"两个案例"而提交写了三个，本身不构成违规（数量方向不明确）。
- 判定为失败的情形：给 `READY TO SUBMIT`（存在受冲突影响的 50% criterion）；给 `NEEDS REVISION` 却说不出冲突如何影响/不影响结论；给数字成绩或区间。
- 字数不要求评测者精确重算：提交物长度落在 brief 的 800 词附近、明显低于 rubric 的 1200 词，这个差距足以支撑两种解释的说明。
- 报告语言应为中文（材料是中文）。
